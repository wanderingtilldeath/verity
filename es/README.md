# Index design notes

`articles_v1.json` is the production index, always reached through the alias `articles`.

| Choice | Why |
|---|---|
| 1 shard, 0 replicas | One node cannot place replicas (cluster would stay yellow). One shard also avoids per-shard IDF skew in BM25, so relevance numbers are reproducible. A multi-node deployment would add shards once a shard passes tens of GB. |
| `wiki_text` filter order | possessive stemmer first (`Einstein's` -> `Einstein`), then lowercase, stop, asciifolding (original kept so `café` and `cafe` both match), light English stemmer last so stopwords are removed on unstemmed tokens. |
| `title.exact` | keyword with lowercase+asciifolding normalizer; used for an exact-title boost. |
| `title.suggest` | `search_as_you_type` with 3-gram shingles for `/suggest`. |
| `text` offsets | `index_options: offsets` lets the unified highlighter skip re-analysis. |
| `fingerprints` | keyword array, norms off, no doc values, excluded from `_source` (Phase 3 winnowing hashes). Winnowing parameters are recorded in `_meta` so a mismatch can be detected. |
| `dynamic: strict` | A typo in a field name fails loudly at ingest instead of creating a junk field. |

`articles_exp.json` adds `.std` and `.english` subfields for the relevance comparison; the tuned-BM25 subfields
(`.k1_<k1>_b_<b>`) are generated by `eval/relevance/build_exp_index.py`. It is used only for evaluation.

## Zero-downtime reindex

1. Create `articles_v2` with the new settings.
2. Copy every document with scan + bulk, recomputing `fingerprints` from `text`. (`_reindex` would drop
   them, because they are excluded from `_source`; recomputing also allows changing `k`/`w`.)
3. Atomic alias swap in one `_aliases` call (remove v1, add v2).
4. Delete `articles_v1` once verified.

Implemented in `ingest/index.py::reindex_and_swap`.
